# Build report — CampX AI

Built and verified in a Linux sandbox (Python 3.12.3, Node 22, npm 10). **No Windows, no PowerShell, no real CampX access, no real browser.**

## Features implemented

* FastAPI backend: config, CampX client, per-user SQLite sessions (Fernet-encrypted upstream state, hashed session ids, expiry, logout invalidation, per-user session cap), CSRF (signed double-submit cookie + Origin/Referer check), CORS allow-list, login rate limiting (per account and per IP), security headers, redacting log filter, size limits, separate admin credential.
* Login using the observed CampX request (URL, headers, body shape); handles 400/401, 403, 429, 5xx, timeouts, malformed JSON, and **MFA-required → refused, no session**.
* Configurable follow-up authentication (`cookie` / `bearer` / `header`), configurable data paths (timetable prefilled with the observed route), `campx` / `imported` / `auto` data sources with explicit `source` in every response.
* Normalizers for timetable, profile, attendance, subjects (known structures only; unknown → `422`), JSON import endpoints (+ status/delete), attendance maths, today/next-class logic.
* React + Vite UI: Login, Overview, Profile, Timetable (day/week), Attendance (adjustable target), Subjects (search), Settings (data source, connection state, imports, logout); skeletons, empty and error states; responsive; no browser storage of credentials.
* Docs: README, SECURITY, steps_for_chatgpt, API, TROUBLESHOOTING; fake sample JSON; PowerShell scripts; redaction helper.

## Configuration you must supply

1. `APP_SECRET_KEY` (auto-generated by `scripts\setup.ps1`).
2. `CAMPX_CLIENT_HEADER_VALUE` — copy from your own browser's login request (README).
3. Verify/adjust `CAMPX_AUTH_MODE`, `CAMPX_TIMETABLE_PATH`; discover `CAMPX_ATTENDANCE_PATH`, `CAMPX_PROFILE_PATH`, `CAMPX_SUBJECTS_PATH` via DevTools (steps_for_chatgpt.md §11).
4. For deployment: `APP_ENV=production`, `FRONTEND_ORIGIN` (https), optional `ADMIN_TOKEN`.

## Known limitations

No MFA; no silent re-login after CampX session expiry (passwords are intentionally not stored); in-memory login limiter; SQLite single-server; photos behind CampX auth won't load; whether third-party use of CampX login is permitted is for you to confirm with CampX/GNITC terms — if not, use `DATA_SOURCE=imported`.

## What was built
* `backend/app/attendance_engine.py` - exact-integer (`Fraction`) threshold maths: classes needed, classes you can miss, scenario projection, recovery planning. Percentages are display-only.
* `backend/app/session_model.py` - dated session model (keeps `id`, `sessionDate`, period count, lab group, completed/suspended). De-duplicates by upstream id.
* `backend/app/attendance_store.py` + 2 new tables (`attendance_imports`, `attendance_adjustments`, created with `IF NOT EXISTS`, so existing local databases upgrade on next start; no deletion needed).
* `backend/app/routes/attendance_plan.py`: `GET /api/attendance/forecast`, `POST /api/attendance/adjustments`, `DELETE /api/attendance/adjustments`, `POST /api/attendance/scenario`.
* Attendance import is now idempotent: `created` / `unchanged` / `reactivated`, keyed by a content fingerprint; the original payload is stored untouched. Duplicate subjects are rejected.
* Frontend: new Attendance page (subject cards, source labels, recovery text, Present/Absent per upcoming session, what-if calculator, reset, multi-period lab counting switch).
* Timetable: duplicate removal is now a reusable `dedupe_entries()` that is also applied when stored imports are read.

* `.gitignore`: `saved*.json` (see Security).

## Timetable duplicate investigation
Evidence from the structure of a real response (values not inspected): 522 records, 522 unique ids, 93 dates (2026-07-06 to 2026-11-05), weekday of `sessionDate` equals `timetableSlot.day` in all 522 records. The current normalizer turns this into 54 weekly entries; 7 pairs share day/time/subject and differ **only by faculty** (parallel lab batches), which are legitimately distinct.
**I could not reproduce "many repeated sessions" with the current code and that data.** Most likely explanations (unproven): (1) an import saved before dedup existed was still stored with repeats - fixed by cleaning on read; (2) a stale backend/frontend build. If repeats persist after restarting both servers, send the *count of entries per day* from `/api/timetable` (no names).

## Known limitations / unverified
* **Official CampX attendance is not wired up** (`CAMPX_ATTENDANCE_PATH` is empty). Forecasts use imported JSON; a live attendance source would be shown read-only.
* The timetable response contains a per-session `studentAttendance.status` flag. Its meaning (present vs absent) is **unverified**, so it is not used for any figure.
* How the institution counts a 2-period lab (one class or two) is **unverified**. Default: one class per session record; `lab_units=period` counts each period. Notes say "approximate".
* A student's lab batch cannot be identified for future sessions, so upcoming batch sessions are not counted until you mark them.
* Present/Absent applies only to upcoming, unsuspended timetable sessions. An updated import starts with a clean ledger; re-importing the older identical file restores its ledger.
* The 256 KB import limit (`MAX_IMPORT_BYTES`) is smaller than a real full-semester timetable (~1.7 MB), so that file cannot be imported by hand; live fetch has no such limit.
* Each Present/Absent click re-fetches the forecast (one request); there is no optimistic local update.
* Not done this session: redesign of Login/Overview/Profile/Settings/Subjects, bottom navigation for mobile, import-form UX changes.
* Remaining npm findings need major upgrades (Vite 8, React Router 7). The Vite/esbuild ones affect only the local dev server, not the production bundle. The React Router ones concern redirects built from untrusted paths; this app uses fixed internal links.

## Security
* New routes use the existing session + CSRF + origin middleware (tests assert 401 without login, 403 without CSRF) and filter every query by `user_key`. Adjustments are bound to one import, with FK + unique constraints.
* **`saved.json` and `saved-profile.json` in the project root look like real CampX responses (personal data).** They were not committed to any ignore list before; they are now in `.gitignore`. Do not upload or commit them; consider deleting them.
